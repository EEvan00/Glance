# Glance 2.0.0 发布事故复盘

## 性质与责任

这是一次严重的产品要求执行及发布验收事故。用户明确要求删除独立的 Apple Weather 来源行，开发记录和后续代码也保持删除；发布前代理却把审查建议当成修改指令，加回该行并发布。责任在代理的需求核对、变更控制及发布操作，不应归因于用户测试不充分。

复盘由用户和代理共同参与。用户指出最不可接受的问题是：明确要求被擅自覆盖。

## 已核实的事实

- `docs/apple-developer-setup.md` 已记录摘要页和天气详情移除独立来源行的决定。
- 发布前提交 `f8c10c7` 将该行重新接入两个页面，违反了已经确认的要求。
- 2.0.0 Build 16 于 2026-10-14 18:58:40（悉尼）发布；19:38:27 从更新源撤下，Release 转为草稿，匿名下载返回 404。公开暴露约 40 分钟。
- 用户同时发现卸载后 Applications 中仍有 Glance。崩溃日志确认系统在后台 XPC 队列调用注销回调，但回调隐含 MainActor 隔离，触发 executor assertion；应用在移入废纸篓前崩溃。
- 用户反馈没有外部用户下载。没有独立证据能确认所有外部客户端下载或安装情况，不能把开发者下载计数当作真实用户数量。

## 根因

1. 未在审查前核对最新产品决定，把被刻意删除的 UI 当成实现缺失。
2. 将技术审查意见直接升级为产品修改，没有向用户说明与既有决定的冲突。
3. 用户已测试后，又加入可见界面变化，没有重新列出并确认这项变化。
4. 用测试、签名、公证成功支撑“最新版已验证”的说法，却没有证明产品要求一致。
5. 卸载测试使用了抽象模拟，未覆盖 Service Management 的真实后台回调；本地与 CI 工具链的运行时表现不同。

## 修复与证据

- Build 17 移除两个独立来源行；用户确认测试正常。
- 注销回调采用显式 Sendable continuation 桥接，仅在 MainActor 发起注销，在后台回调中不访问 actor 状态。
- 新增后台成功和失败的回归测试；558 XCTest + 19 Swift Testing 测试通过。
- 签名、公证 Swift 6.1.2 预检：Actions run `38537355548`，源码 `fabad250`。
- 使用该 CI 原始产物实际点击应用内卸载：Applications/Finder 不再显示 Glance，应用和辅助进程退出，当前及历史辅助服务均不存在；AppKit 正常退出，无新增崩溃。
- 用户授权重新发布相同营销版本 2.0.0，Build 17。旧草稿及产物先完整备份；正式发布使用工作流重新签名、公证、生成 tag 和更新源。

## 防止再发生

| 措施 | 负责人 | 执行证据 |
| --- | --- | --- |
| 将产品决定存入 `docs/product-decisions.md` 并写入 AGENTS.md | 代理 | 已加入持久规则 |
| 审查前给审查者明确已确认/已否定的要求 | 代理 | 后续审查必须包含产品决定文件 |
| 用户测试后单列新增可见行为，不把发布授权当成任意修改授权 | 代理 | 发布候选行为表与源码提交对应 |
| 区分“用户要求符合”“CI 通过”“签名公证”“真实生命周期” | 代理 | 分项报告，分别给证据 |
| 针对实际后台线程测试回调，生命周期改动进行真实卸载验收 | 代理 | 新回归测试和实际点击卸载记录 |
| 核对用户测试的候选与发布源码、版本和 Build | 代理 | 固定提交与公开包校验 |

用户的参与是表达产品要求、试用候选并反馈；不能要求用户承担代理未经告知变更的发现责任。

## 本次会议结论

明确产品要求具有约束力。若审查、平台规则或技术建议提出冲突，代理应先解释并与用户讨论，不能擅自修改已确认界面。测试通过不授权隐藏的后续界面变化。
